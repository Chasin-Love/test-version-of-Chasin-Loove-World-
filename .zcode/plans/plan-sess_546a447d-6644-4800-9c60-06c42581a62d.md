## Part B — Foundation & Health upgrades (this wave)

Ordered so each step is independently verifiable (`npm run typecheck` + `npm run build` after every step):

1. **Purge dead code (~1,600+ lines)**
   - Delete `src/engine/kamui.ts` (733-line `KamuiEffect`, superseded by in-engine Kamui systems; remove its re-export from `src/engine/index.ts`).
   - Remove unused GLSL exports from `src/engine/shaders.ts`: `blackHoleVert/Frag`, `kamuiSpacetime*`, `kamuiSingularity*`, `kamuiTunnel*`, `kamuiTear*` (~450 lines) — grep first to confirm zero importers.
   - Remove duplicate executor file `src/backend/storage/executors.ts` (95% copy of `src/backend/executors/index.ts`) after confirming `src/backend/index.ts` exports only the canonical one; keep a one-line re-export shim if anything still imports the old path.
   - Delete the unused compatibility shims `src/storage/*` (12 files), `src/db.ts`, `src/realities.ts` — grep to verify nothing imports them, then remove (note: generated reality templates reference `../types`; fix template paths instead of keeping stubs).
   - Move the committed dev-junk reality `src/realities/test/` into `src/realities/bin/` so it stops shipping in the live multiverse.

2. **Fix the reality server's security holes**
   - `server.ts` `create-folder`: `customFolderName` from the request body is used unfiltered in `path.join` (path traversal — `../..` escapes `src/realities`). Apply the same alphanum sanitizer to every path component in `create-folder`, `rename-folder`, `delete-folder`, bin move/restore/purge, and the `DELETE /api/realities/:id` handler; resolve the final path and assert it stays inside `src/realities/` before any fs write/rm.
   - Same containment assert inside `src/server/realityDaemon.ts` (`moveToBin` fallback and restore paths).

3. **Centralize the scale/hierarchy constants (kill the 3-way drift risk)**
   - Create `src/realities/hierarchyStages.ts` (or extend `hierarchyTypes.ts`) exporting one `HIERARCHY_STAGES` table: label + zoom dial + description.
   - Rewire `MultiverseBar.hierarchyStages`, `engine.zoomToHierarchy`'s dial array, and `CosmicWebHUD.getLODInfo` to consume it.

4. **De-duplicate shared utilities**
   - Single `makeGlowTexture` (engine.ts vs UniverseSurfaceManager.ts), single math helpers (`smoothstep/damp/clamp`) module, shared GLSL `NOISE` chunk (shaders.ts vs kamui.ts — moot after kamui.ts deletion), `synthBars`/`readAsDataURL`/`WaveStrip` consolidated into `src/ui/lib.ts`.

5. **Behavioral correctness fixes (small, safe)**
   - Remove the double `POST /api/realities/create-folder` (CreateRealityModal fires it AND `state.ts` `createReality` fires it again) — keep only the state-action call.
   - Stop `primeState` (state.ts:99) from back-dating the newest diary entry's `updatedAt` to fake streaks — display logic should compute streaks without mutating user content.
   - Replace `src/realities/index.ts` template path fragility: generated reality templates should import from a path that exists as a real module.

6. **Light decomposition of the engine god-class (highest-value extraction only)**
   - Extract from `engine.ts` into modules under `src/engine/systems/`: `stageThresholds.ts` (the ~12 magic dial constants + band windows), `portalController.ts` (the 9-phase portal FSM + singularity + vortex uniforms), and `levelSystem.ts` (`updateLevels` + label ladder). `UniverseEngine` delegates; no behavior change.
   - VaultUI (4,534 lines) decomposition is explicitly **deferred** to a later wave (too risky to bundle with this one); it's documented in ANALYSIS.md's debt register with a proposed split.
